# 启动包质量门

交付任何启动草案前做这份自检。缺失项不要隐形跳过，写进“待确认问题”。

## 必过项

- [ ] 已判断 S/M/L，或明确说明暂按哪个量级处理。
- [ ] 没有超过两轮访谈；第二轮后已经输出草案。
- [ ] 写清了要解决谁的什么问题。
- [ ] 写清了为什么现在做。
- [ ] 至少有 1 个可衡量成功指标。
- [ ] 有 In / Out 范围，尤其是 Out。
- [ ] RACI/DACI 中每个关键决策只有一个最终拍板人。
- [ ] 有里程碑和阶段关卡，关卡包含 exit criteria。
- [ ] 有 Top 风险、应对策略和 owner。
- [ ] 所有缺失信息都标成 `TBD（负责人 / 截止日）`。

## 按量级裁剪

- S：只需要目标、验收标准、负责人、下一步；不要输出完整 PR/FAQ 或六页纸。
- M：一页章程 + RACI + 里程碑 + 启动会议程即可。
- L：补 PR/FAQ 或六页纸、RFC、阶段关卡、风险登记、正式启动会。

## AI 项目加检

- [ ] 有 eval 指标或验收数据集。
- [ ] 有灰度放量计划。
- [ ] 有安全、隐私、失败模式分析。
- [ ] 有不可上线的红线。

## 常见跑偏反模式

- 一上来输出完整方案，没有先判断信息是否足够。
- 问题一次问太多，像调查问卷。
- 一直追问不产出草案。
- 成功指标写成“用户体验更好”“效率提升”，没有数字或验收判据。
- 只写 In，不写 Out。
- RACI 里多个 A，实际没人拍板。
- 里程碑只有日期，没有关卡放行标准。
- 把普通任务排期误判成项目启动。
