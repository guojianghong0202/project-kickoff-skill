# M 型项目启动包样例：销售线索录音分析工具

> 这是一个填好的示例，用于展示 project-kickoff skill 的输出形态。内容为虚构场景，可按实际业务替换。

## 访谈输入摘要

- 问题：销售顾问每天要手动复盘大量客户通话，线索质量判断慢，高风险话术难以及时发现。
- Why now：团队已经沉淀了 3 个月录音数据，销售团队扩张后人工质检跟不上。
- 目标用户：一线销售顾问、销售主管、质检负责人。
- 项目体量：M。预计 4-6 周，产品、后端、AI 工程、销售运营共 4-5 人参与。
- 约束：先做内测，不接管现有 CRM，不处理实时通话。
- 待确认：数据合规审批负责人、历史录音可用比例、接入 CRM 的具体接口人。

## 一页项目章程

项目名称：销售线索录音分析工具

负责人（owner）：产品负责人 TBD（销售运营负责人 / 2026-07-12）

发起人 / 出资人（sponsor）：销售运营负责人

日期：2026-07-08

目标量级：M

### 一、为什么做

销售团队每周产生大量客户通话录音，目前主要靠销售顾问和主管人工复盘。人工复盘耗时长、标准不一致，高意向线索和高风险话术容易漏掉。若不处理，随着销售团队扩张，主管复盘和质检会成为增长瓶颈。

### 二、目标与成功指标

目标：在 6 周内完成一个内测版本，支持通话录音转写、摘要、风险标签和线索评分，先服务 10 名销售顾问和 2 名销售主管。

成功指标：

- 内测销售顾问每周复盘时间减少 30%。
- 录音摘要被销售主管标记为“可用”的比例达到 85%。
- 高风险话术召回率达到 80%。
- 试点 2 周内至少 70% 的内测用户每周使用 3 次以上。

### 三、范围

本次做（In）：

- 上传或拉取历史通话录音。
- 自动转写、摘要、提取客户意向点。
- 标记高风险话术和待跟进事项。
- 输出线索评分和主管复盘视图。
- 内测数据看板。

本次不做（Out）：

- 不替换 CRM。
- 不做实时通话监听。
- 不做自动外呼。
- 不做面向全销售团队的正式发布。
- 不做复杂权限体系，只覆盖内测名单。

### 四、关键干系人与决策权

|---|---|---|---|---|---|
| 项目目标与范围 | R | C | C | A | I |
| 数据合规审批 | C | I | I | R | A |
| 模型评估方案 | C | R | I | A | C |
| CRM/录音接口 | C | I | R | A | I |
| 内测放行 | R | C | C | A | C |

### 五、里程碑与关卡

阶段 1：数据与合规确认（第 1 周）

- 交付物：录音样本清单、合规审批结论、字段说明。
- 关卡放行标准：可合法使用的样本不少于 200 条；合规审批无阻断项。
- 决策：Go / Recycle / Kill。

阶段 2：MVP 内测版（第 2-4 周）

- 交付物：转写、摘要、风险标签、线索评分、基础看板。
- 关卡放行标准：摘要可用率 >= 75%，高风险话术召回率 >= 70%，内测用户可完成端到端流程。
- 决策：Go / Recycle / Kill。

阶段 3：内测验证（第 5-6 周）

- 交付物：10 名销售顾问、2 名主管的试点结果和复盘报告。
- 关卡放行标准：复盘时间减少 30%，摘要可用率 >= 85%，周活跃使用率 >= 70%。
- 决策：Go / Recycle / Kill。
